# ADS8864 与 STM32F302 SPI 接口改进稳定版技术说明

## 0. 背景

- ADC：ADS8864，16 位、400 kSPS SAR ADC，SPI 读取。
- MCU：STM32F302C8T6，72 MHz；TIM15_CH2（PB15）输出 CONVST 脉冲，PSC=0，1 计数 = 13.9 ns。
- SPI2：仅接收主机，9.0 Mbit/s，读 16 bit 约需 1.78 µs；MISO（PB14）同时接到 EXTI2（PB2）作中断输入，构成 3 线 CS 模式的"忙指示"检测。
- 原始工程采用 3 线 CS 模式（DIN 在 CONVST 上升沿为高 → CS 模式），但存在若干时序缺陷，改进版改为"3 线 CS 有忙指示 + 冻结定时器"方案，现已读数正常。

---

## 1. 原版的不足

### 1.1 CCR2 = 50，CONVST 脉宽 694 ns，落在"模糊窗口"内，忙指示时有时无

ADS8864 是否输出忙指示（busy indicator），由**转换结束（EOC）瞬间 CONVST 的电平**决定：

- EOC 时 CONVST 为低 → 输出忙指示位（DOUT 拉低）；
- EOC 时 CONVST 为高 → 无忙指示（DOUT 保持三态，直到下次 CONVST 下降沿释放 MSB）。

而转换时间 t_conv = 500 ns（最小）~ 1300 ns（最大），**逐次转换、随温度电压漂移**。原版 CCR2 = 50，即 CONVST 高电平脉宽 = 50 × 13.9 ns ≈ **694 ns，恰好落在 500~1300 ns 窗口中间**：

- 本次转换若 < 694 ns 结束 → EOC 时 CONVST 仍为高 → **无忙指示**；
- 本次转换若 > 694 ns 结束 → EOC 时 CONVST 已变低 → **有忙指示**。

结果是有/无忙指示**逐次随机**。危害有两层：

1. **IRQ 触发时机随机**：有忙指示时，下降沿出现在 EOC（busy 位拉低）；无忙指示时，DOUT 一直三态，要等到数据 MSB 有效位为 0 才有下降沿——触发时机依赖于被测电压大小，甚至根本不触发。
2. **数据格式随机变化**：有忙指示时帧是 17 bit（BUSY + D15~D0），无忙指示时是 16 bit。代码固定只读 16 bit，若某次多出一个 busy 位，数据整体右移 1 位，幅值直接减半——这是**随机出现的 50% 量级的灾难性误差**，远比丢失 1 个 LSB 严重。

### 1.2 中断里改 CCR 可能根本没生效（开启了 CCR 预装载）

TIM15 的 CH2 开启了输出比较预装载（OC2PE = 1，`LL_TIM_OC_EnablePreload`）。此时 `WRITE_REG(TIM15->CCR2, x)` 写的只是**预装载寄存器**，真正参与比较的影子寄存器要等**更新事件（UEV）**才更新。PWM 输出比较模式下，更新事件 = 计数器溢出（CNT 到 ARR 回卷）。

原版中断里的流程：

```c
Convst_Reset();          // CCR2 = 0  → 只写进预装载寄存器
TIM15->CNT = 0;          // 计数清零，但 CCR2 影子值还是 50
... SPI 读取 ...
Convst_Set(50);          // CCR2 = 50 → 又写进预装载寄存器
```

问题在于：

1. `CNT = 0` 清零后，**影子寄存器里仍是 50**，PWM1 模式下 CNT < CCR2 立即成立 → **CONVST 马上产生一个上升沿**，在 SPI 还没读完时就启动了下一次转换。新转换一开始 DOUT 就三态，正在进行的 SPI 读取被直接截断，读到的就是上一次数据的残影或全 1。
2. 随后的 `Convst_Set(50)` 只是预装载，要等到当前周期溢出才生效；整个"先 0 后 50"的操作在影子寄存器层面近乎无效，实际时序由溢出事件和影子值主导，和代码意图完全脱节。

也就是说：**在中断里动态改 CCR 来控制 CONVST，在开启预装载的前提下是一条走不通的路**，写出来的代码和实际波形对不上。

### 1.3 其他缺陷

- **SPI 超时即死锁**：`HAL_SPI_Receive` 一旦超时返回非 HAL_OK，恢复语句（重开 EXTI、重开定时器）在 `if (HAL_OK)` 里面，系统将永久停摆。
- **读取期间丢失忙指示边沿**：读 SPI 时关闭了 EXTI，若上一次遗留状态异常，忙指示下降沿落在屏蔽窗口内，该次采样被整体丢弃，且无任何计数/告警手段。
- **DOUT 无强上拉**：3 线有忙指示模式要求 DOUT 在三态期间被上拉（数据手册的忙指示电路标配外部上拉电阻），板上没有外部上拉，只有 PB14 内部弱上拉（约 40 kΩ），三态期间电平爬升慢，是杂散边沿的隐患（调试中出现的 cnt = 18 提前中断、读出 0xFFFF 即与此相关：转换尚未结束时 DOUT 仍在三态，弱上拉把线拉成全 1，SPI 读出 65535）。

## 2. 改进版方案及好处

### 2.1 方案：3 线 CS 有忙指示 + 冻结定时器

1. **CCR2 固定为 28**（脉宽 ≈ 390 ns < t_conv 最小值 500 ns）：保证 EOC（500~1300 ns）时 CONVST **必然已经是低电平** → **每次都有忙指示**，工作模式彻底确定，不再随机。CCR2 从头到尾不再修改。
2. **中断里不改 CCR、不清 CNT，只冻结定时器**（`CLEAR_BIT(TIM15->CR1, TIM_CR1_CEN)`），SPI 读完再恢复（`SET_BIT`）。

```c
void ADS8864_ReadValue(void)
{
    if (__HAL_GPIO_EXTI_GET_IT(IRQ_Pin) != RESET)
    {
        __HAL_GPIO_EXTI_CLEAR_IT(IRQ_Pin);
        CLEAR_BIT(EXTI->FTSR, IRQ_Pin);
        HAL_NVIC_DisableIRQ(IRQ_EXTI_IRQn);
        CLEAR_BIT(TIM15->CR1, TIM_CR1_CEN);      // 冻结：时钟停摆，CONVST 保持当前电平

        if (HAL_SPI_Receive(&ADS8864_SPI_Port, adc_data, 2, 0x0F) == HAL_OK)
        {
            adc_rawdata[adc_counter] = (adc_data[0] << 8) | adc_data[1];
            adc_counter++;
            if (adc_counter == ADC_SAMPLE_SIZE) adc_counter = 0;
        }
        SET_BIT(EXTI->FTSR, IRQ_Pin);            // 恢复语句移出 if，见 2.3
        HAL_NVIC_EnableIRQ(IRQ_EXTI_IRQn);
        SET_BIT(TIM15->CR1, TIM_CR1_CEN);
    }
}
```

### 2.2 为什么冻结比改 CCR 好

| 对比项 | 中断里改 CCR | 冻结定时器 |
|---|---|---|
| 预装载竞态 | 有：写的是预装载寄存器，生效时机依赖溢出，和 CNT 清零叠加会产生意外上升沿 | 无：完全不碰 CCR |
| CONVST 波形 | 受影子寄存器更新时机影响，不可预测 | 严格由固定 CCR2 决定，每次一致 |
| 采样周期 | 不规则 | 时钟停摆时间 + 剩余计数 = 恒定的整数个计数，周期均匀 |
| 代码复杂度 | 要处理预装载/影子/UG 一堆细节 | 两行位操作 |

冻结期间 CNT 停在 36~94（EOC 落在 500~1300 ns），恢复后定时器从冻结点继续走完剩余计数，**每个采样周期中"定时器实际运行的时间"恒等于 ARR+1 个计数**，采样间隔均匀，对后续均值滤波、频谱分析都友好。同时冻结段天然满足 t_ACQ ≥ 1.2 µs 的要求——SPI 读取时间就是采样保持电容的采集时间，两者重叠，互不等待（ADS8864 的采集与上一次数据的读取本来就是重叠进行的）。

### 2.3 其他同步修正

- **恢复语句移出 `if (HAL_OK)`**：SPI 超时只丢一个样本，不再死锁。
- **首次写 CCR2 后手动产生更新事件**（`SET_BIT(TIM15->EGR, TIM_EGR_UG)`）再启动 PWM，确保影子寄存器装载的是 28 而不是上电默认值 0。
- **模式确定后的误差可忽略**：固定有忙指示时，16 个 SCLK 读到的是"BUSY + D15~D1"，丢失 D0，等效数据右移 1 位——两点标定（零点 + 满度）完全吸收这一系统性偏移，残余误差 ≤ 1 LSB。

## 3. 为什么 ARR 从 179 改为 1079

72 MHz 下：

- ARR = 179 → 周期 180 计数 = 2.5 µs → **400 kHz**，顶满 ADS8864 的最高转换速率；
- ARR = 1079 → 周期 1080 计数 = 15 µs → **66.7 kHz**。

改动原因有三：

1. **STM32 侧根本吃不下 400 kHz**。每次中断里 HAL 轮询读 16 bit，SPI 传输本身约 1.78 µs，加进出中断、标志操作，ISR 总耗时约 2.5 µs；冻结方案下单样本周期 = 定时器运行 2.5 µs + ISR 约 2.5 µs ≈ 5 µs，实际采样率只有 180~200 kSPS，且中断优先级为 0、频率约 200 kHz，**一半以上的 CPU 被 ISR 吃掉，主循环明显变慢**（这正是调试中"while(1) 转不动"的原因）。ARR = 179 只是把定时器挂在了一个系统兑现不了的速率上。
2. **66.7 kHz 本来就是本设计的目标速率**。原理图注释写明"目前 STM32F302 采样速率 66.7 kHz"：32 点均值滤波后输出速率 ≈ 66.7 k / 32 ≈ **2 kHz**，对 4-20 mA 这类缓变过程量已经绰绰有余。ARR = 1079 让定时器速率回到设计值。
3. **降速换稳定**。改用 ARR = 1079 的根本原因是：ARR = 179 时周期只有 2.5 µs，留给 HAL 和中断本身的开销实在太短。调试中观察到的两种中断入口正好说明这一点——CNT = 169 时正常进入中断、读到正常数据；而 CNT = 18 进入中断，表明这次 IRQ 本该在上一个周期内被处理，但代码执行有开销、需要时间，等真正进入 ISR 时定时器已经溢出进入了下一周期，CNT 才刚数到 18（约 250 ns，转换尚未完成）。按 ADS8864 手册，此刻 DOUT 处于三态，线上只有上拉维持的高电平，SPI 读到的自然全是 1，即 65535。改成 ARR = 1079 后周期拉长到 15 µs，HAL 和中断开销只占其中很小一段，中断处理再也不会被拖到下一周期，杂散读数随之消失。（调试出现的问题）
